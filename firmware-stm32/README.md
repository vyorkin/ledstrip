# ledstrip core (host)

Переносимое ядро STM32-версии: цифровые полосы, огибающие, АРУ, удар,
кадры WS2812 и дребезг кнопки. Собирается обычным `cc`, плата не нужна.

```sh
make test
```

## Файлы

| Файл | Что делает |
|---|---|
| `include/ledstrip/dsp.h`, `src/dsp.c` | три biquad band-pass, выпрямитель, огибающие, АРУ, удар |
| `include/ledstrip/frame.h`, `src/frame.c` | позиции 8.8, отражение, режимы, пакеты GRB |
| `include/ledstrip/button.h`, `src/button.c` | дребезг 5 кадров, одно событие на нажатие |
| `include/ledstrip/ws2812.h`, `src/ws2812.c` | GRB 360 байт → 2880 полуслов CCR3, MSB первым |
| `test/test_core.c` | АЧХ, АРУ, удар, кнопка, режимы, кадры, кодирование WS2812 |

## Контракт

- Вход: `dsp_process()` на каждый отсчёт 96 кГц; `x` в `[-1, 1]`.
- Кадр: `dsp_frame()` ровно 200 Гц (каждые 480 отсчётов).
- `DspFrame::brightness` — 0…204, `DspFrame::beat` — удар.
- Кадр ленты: `frame_step()` раз в кадр, `frame_render()` — 360 байт GRB.
- Передача: `ws2812_encode()` — 360 байт GRB в 2880 полуслов `CCR3`
  (0 → 38, 1 → 75), MSB первым; T0H/T1H/T0L/T1L ≈ 0.38/0.75/0.87/0.50 мкс.
- `frame_init()`: режим 0, `flip=0`, позиции 10/40/80.
- `frame_set_mode()`: меняет только `dir`; `flip` и `hitcnt` сохраняются.
- `frame_next_mode()`: 0→1→2→3→0, только `dir`; позиции, `flip` и
  `hitcnt` сохраняются.
- `frame_step()`: `beat` дважды переключает `flip`; отражение на краях
  меняет `dir`.
- Кнопка: `button_frame()` раз в кадр 200 Гц; `true` ровно один раз за
  нажатие после 5 подряд нажатых кадров. Отпускание сбрасывает счётчик,
  удержание не повторяет.

## Числа

- Полосы: 141 Гц Q1.46, 4.82 кГц Q1.54, 13.2 кГц Q1.12.
- Огибающая: атака 2 мс, спад 150 мс.
- Пик для АРУ: атака 1 мс, спад 300 мс.
- АРУ: цель 0.5, предел 0.5…8.0, спад 50 мс, возврат 500 мс.
- Удар: прирост 0.05, минимум 0.12, пауза 40 кадров.
- Яркость: `204 * (level/0.5)^1.8`, ниже 0.02 — ноль.

## Целевая интеграция

Шаги 1–5 собраны в `target/`: PLL 100 МГц (HSE 25 МГц), heartbeat
PC13, захват PA1 через TIM2 TRGO + ADC1 + DMA2 Stream 0, кадр на PB0
через TIM3_CH3 + DMA и кнопка PA0. Остальные шаги ждут плату WeAct
STM32F411CE и ленту; порядок, который не меняет это ядро:

1. Тактирование 100 МГц (HSE 25 МГц + PLL) — готово в `target/`.
2. TIM2 → TRGO 96 кГц → ADC1 PA1 → DMA circular, два полубуфера по 480 —
   готово в `target/` (символы `g_dsp_frame`, `g_dsp_frame_count`,
   `g_adc_overruns`).
3. По половине/полному буферу — `dsp_process()`, каждые 480 — `dsp_frame()` —
   готово в `target/`.
4. Каждый `DspFrame` → `frame_step()` → `frame_render()` → 2880 полуслов
   CCR3 → TIM3_CH3 PB0, 200 кадров/с — готово в `target/`; передача
   блокирует CPU на 3.6 мс, DMA АЦП в это время не останавливается.
5. PA0 — кнопка: 5 кадров подряд, затем `frame_next_mode()` — готово в
   `target/`; сэмпл раз в `DspFrame`, смена режима до шага этого кадра.
6. WDG → `frame_step()`.

Проверка на железе: PA1 (смещение 1.65 В), PB0 (≈4.7 В, T0H/T1H), лента,
кнопка. HIL-тестов нет.
